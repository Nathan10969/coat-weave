# KG Adapter Review Follow-ups

The user approved resolving the three review observations and merging the
opt-in adapter into GitHub `main`. Reviewed adapter: `868bed7`; previous public
`main`: `18cbfef438fb38af4bcd99ed2e6457aaba26b2ca`.

## Changes

1. The search tool description permits English translations of concepts already
   present in a question. They are search-text aids, not new hard filters. No
   Chinese keyword rules, translation service or extra model call was added.
   This addresses the prompt restriction, but does not establish improved recall;
   Chinese questions still require real-model/corpus acceptance before KG rollout.
2. HTTP 400 can expose four fixed input-validation reasons already returned by
   the KG service. Arbitrary backend messages remain hidden, as do all HTTP 500
   bodies. This is an error-message allowlist, not a new semantic filter or retry.
3. KG schema loading is lazy. Ordinary Milvus check/build/start no longer needs
   Python, generated KG schemas or the parent service source. KG builds explicitly
   run `npm run build:kg`; the complete test suite also exports the shared schemas.
   A missing KG schema gives an actionable build instruction, never a fallback.

The original Python retrieval, normalization, expansion and statistics modules,
SDK version, dependency lockfile, product prompt, thinking setting and metadata
logger are unchanged. Default retrieval remains Milvus.
